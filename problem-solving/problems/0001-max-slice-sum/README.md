# 0001. MaxSliceSum — 최대 부분합

- **출처**: Codility Lesson 9 (Maximum slice problem)
- **난이도**: Easy~Medium
- **유형**: 배열, DP(Kadane), 누적합
- **작성일**: 2026-08-14

---

## 1. 문제

> 정수 배열 `A`가 주어질 때, **비어있지 않은 연속 부분 수열**의 합 중 최대값을 구한다.

**입력**

- `A`: 길이 `N`의 정수 배열

**출력**

- 부분 수열 합의 최대값 (정수)

**제약조건**

- `N` 범위: `1 ≤ N ≤ 100,000`
- 값 범위: `-1,000,000 ≤ A[i] ≤ 1,000,000`
- 부분 수열은 **비어있을 수 없다** → 원소가 전부 음수여도 답은 음수가 된다

**예제**

| 입력 | 출력 | 설명 |
| :--- | :--- | :--- |
| `[3, 2, -6, 4, 0]` | `5` | `[3, 2]` 구간의 합 |
| `[-3, -1, -9]` | `-1` | 전부 음수 → 가장 큰 원소 하나 |
| `[10, -100, 10]` | `10` | 큰 음수가 구간을 끊는다 |

---

## 2. 접근

- **처음 떠올린 방법**: 모든 `(i, j)` 구간의 합을 직접 계산 → `O(N^2)`.
  `N = 100,000`이면 약 50억 회 연산으로 Performance 점수에서 탈락.
- **누적합(prefix sum)**: `sum(i..j) = P[j] - P[i-1]`. 각 `j`마다 **지금까지의 최소 누적합**을 알면
  `P[j] - min(P[0..j-1])`이 `j`에서 끝나는 최대 구간합. `O(N)`으로 내려간다.
- **최종 선택 — Kadane's algorithm**: 위 아이디어를 배열 없이 변수 2개로 접는다.
  각 위치에서 결정할 건 하나뿐이다. **"이전 구간을 이어받을까, 여기서 새로 시작할까."**
  이전 구간합이 음수면 붙이는 순간 손해다. 그러니 버리고 새로 시작한다.
  공간 `O(1)`이고 구현이 짧아 실수 여지가 적다.

누적합 방식은 오라클(교차 검증용 독립 구현)으로 남겨뒀다. 같은 답을 다른 논리로 얻어야 신뢰할 수 있다.

---

## 3. 알고리즘

```
best    = A[0]      # 지금까지 본 최대 구간합
current = A[0]      # 현재 위치에서 끝나는 최대 구간합

for value in A[1:]:
    if current < 0:
        current = value          # 이전 구간을 버리고 새로 시작
    else:
        current = current + value  # 이전 구간에 이어붙임
    best = max(best, current)

return best
```

핵심은 `best`와 `current`를 **`A[0]`으로 초기화**하는 것. `0`으로 초기화하면
빈 구간(합 `0`)을 허용하게 되어 "전부 음수" 케이스에서 `0`을 반환해 틀린다.

---

## 4. 복잡도

- 시간: `O(N)` — 배열 한 번만 순회
- 공간: `O(1)` — 변수 2개 (`best`, `current`)
- **근거**: `N = 100,000`에서 실측 0.01초 미만. `O(N^2)` 대비 5만배 차이.
  검증 코드에 `1.0초` 상한 가드를 넣어 `O(N)`이 깨지면 실패하게 만들었다.

## 5. 검증

| 케이스 | 목적 |
| :--- | :--- |
| `[3, 2, -6, 4, 0]` | 문제 지문 예제 재현 |
| `[5]`, `[-7]` | 원소 1개 (최소 입력) — 양수/음수 |
| `[-3, -1, -9]` | **전부 음수** — `0` 초기화 버그를 잡는 케이스 |
| `[0, 0, 0]` | 전부 `0` |
| `[2, 2, 2, 2]` | 전부 동일한 양수 (전체 구간이 답) |
| `[-2, 5, -1, 5, -2]` | 중간 음수를 품고 이어붙이는 게 이득인 경우 |
| `[10, -100, 10]` | 큰 음수로 구간이 끊기는 경우 |

| `N = 100,000` 무작위 | 대규모 정답 일치 + 1초 이내 완주 |

## 6. 함정 & 배운 점

- **`best = 0`으로 초기화하면 틀린다.** "비어있지 않은" 조건 때문에 전부 음수인 배열의 답은
  `0`이 아니라 최대 원소다. Codility 히든 테스트가 정확히 이 지점을 찌른다.
  → 제약조건에서 **"비어있을 수 있는가"**를 항상 먼저 확인한다.
- `current = max(value, current + value)`로 써도 동일하지만, `current < 0` 분기로 쓰면
  "왜 버리는가"가 코드에 드러난다.
- **정답 검증에 브루트포스를 같이 쓴다.** 손으로 만든 케이스는 내가 생각한 함정만 잡는다.
  무작위 입력 + `O(N^2)` 정답 비교가 생각 못한 함정을 잡아준다.
- 오라클도 검증 대상이다. 오라클이 틀리면 잘못된 통과 신호를 준다 —
  작은 무작위 케이스에서 브루트포스와 맞춰본 뒤 대규모 검산에 썼다.
