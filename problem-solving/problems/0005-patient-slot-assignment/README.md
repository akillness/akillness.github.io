# 0005. 환자 진료 시간대 배정 가능성 판정

- **출처**: 코딩테스트 유형 (그래프 환원)
- **난이도**: Medium~Hard — 환원을 못 보면 지수 탐색, 보면 선형
- **유형**: 그래프, Union-Find, pseudoforest
- **작성일**: 2026-08-14

---

## 1. 문제

> `N`명의 환자가 각각 **두 개의 서로 다른** 선호 시간대를 갖는다.
> `S`개 시간대에 각각 **한 명만** 배정 가능하다.
> 모든 환자를 선호 시간대 중 하나에 배정할 수 있는가?

**입력**

- `A`: 각 환자의 첫 번째 선호 시간대 (`len(A) == N`)
- `B`: 각 환자의 두 번째 선호 시간대
- `S`: 전체 시간대 개수

**출력**

- 모두 배정 가능하면 `True`, 아니면 `False`

**제약조건**

- `1 ≤ N ≤ 100,000`
- `2 ≤ S ≤ 100,000`
- `1 ≤ A[i], B[i] ≤ S`
- `A[i] != B[i]` (각 환자는 서로 다른 두 시간대를 선호)

**예제**

```
A = [1, 2, 3], B = [2, 3, 1], S = 3   → True   (삼각형: 1→2→3→1 로 돌리면 됨)
A = [1, 1, 1], B = [2, 2, 2], S = 4   → False  (세 명이 시간대 2개에 몰림)
```

---

## 2. 접근

### 버린 방법: 완전탐색 — `O(2^N)`

각 환자가 2택이므로 조합이 `2^N`. `N = 100,000`에서는 논외.
(검증용 오라클로만 남겼다.)

### 버린 방법: 전역 `N ≤ S` 검사

가장 흔한 오답이다. **반례**:

```
A = [1, 1, 1], B = [2, 2, 2], S = 4
N = 3 ≤ S = 4  이지만 답은 False
```

세 환자 모두 `{1, 2}`만 선호한다. 시간대 4개가 있어도 쓸 수 있는 건 2개뿐.
**용량은 전역이 아니라 국소적으로 부족해진다.**

### 관찰: 이건 그래프 방향 부여 문제다

| 문제 언어 | 그래프 언어 |
| :--- | :--- |
| 시간대 | **정점** |
| 환자 (두 시간대 선호) | **간선** `(A[i], B[i])` |
| 환자를 한 시간대에 배정 | 간선을 한쪽 끝점으로 **방향 부여** |
| 시간대당 1명 | 정점당 **들어오는 간선 ≤ 1** |

즉 "모든 간선을 각자 한쪽 끝점에 배타적으로 할당할 수 있는가"가 된다.

### 조건: 각 연결 요소에서 `|간선| ≤ |정점|`

**필요조건** — 요소의 정점이 `V`개면 담을 수 있는 간선은 최대 `V`개.
`E > V`면 비둘기집 원리로 불가능.

**충분조건** — `E ≤ V`인 요소는 항상 배정된다:

- **트리** (`E = V-1`): 아무 정점을 루트로 잡고 모든 간선을 **자식 쪽**으로 방향 부여.
  각 정점은 자기 부모 간선 하나만 받는다. 루트만 빈다.
- **단일 사이클 포함** (`E = V`): 사이클을 한 방향으로 돌리면 사이클 정점이 정확히 하나씩
  받는다. 사이클에 매달린 트리는 사이클에서 **멀어지는 방향**으로.

`E ≤ V`인 그래프를 **pseudoforest**라 부른다. 즉 이 문제는 "입력 그래프가
pseudoforest인가"와 같다.

### 구현: 사이클 개수를 Union-Find로 추적

`E ≤ V`는 "요소당 사이클 최대 1개"와 동등하다. 이걸 직접 추적하면 마지막에 `S`개
정점을 다시 훑을 필요가 없다.

---

## 3. 알고리즘

```
parent[v] = v            for v in 1..S
has_cycle[v] = False

for (a, b) in zip(A, B):
    ra, rb = find(a), find(b)
    if ra == rb:                          # 같은 요소 안의 간선 → 사이클 +1
        if has_cycle[ra]: return False    #   이미 있었다 → E > V
        has_cycle[ra] = True
    else:
        if has_cycle[ra] and has_cycle[rb]:
            return False                  # 사이클 2개를 이으면 E = V + 1
        parent[rb] = ra
        has_cycle[ra] = has_cycle[ra] or has_cycle[rb]

return True
```

`find`는 **반복문 + 경로 압축**으로 쓴다. 재귀로 쓰면 `S = 100,000`에서
재귀 한도에 걸린다.

---

## 4. 복잡도

| | 이 풀이 | 완전탐색 |
| :--- | :--- | :--- |
| 시간 | **O((N + S)·α(S))** | O(2^N · N) |
| 공간 | **O(S)** | O(N) |
| 최대 제약 실측 | **0.27초** (전체 검증 포함) | 논외 |

`α`는 역 아커만 함수 — 실질 상수. 경로 압축이 이걸 보장한다.

### 성능 가드를 만드는 데 실측이 필요했다

처음엔 `(1,2),(2,3),(3,4),...` 거대 사슬을 성능 케이스로 썼다. **그런데 이건 경로
압축을 전혀 자극하지 않는다.** `parent[rb] = ra` 방향 때문에 모든 노드가 곧바로
루트 `1`에 붙어 트리가 **평평**해진다(최대 깊이 1). 압축을 지워도 같은 속도였다.

역방향 사슬 `(2,1),(3,2),...`은 깊이 99,999를 만들지만 **여전히 안 느리다** —
매 간선 처리 시점에 조회하는 노드가 항상 그 요소의 현재 루트라서 사슬을 타고
올라가지 않는다.

실제로 압축이 필요한 형태는 **깊은 사슬을 만든 뒤 가장 깊은 노드를 반복 조회**하는 것:

```python
half = S // 2
deep_a = list(range(2, half + 1))      # (2,1),(3,2),... → 1 이 사슬 맨 아래
deep_b = list(range(1, half))
for x in range(half + 1, S + 1):       # (1, x) 반복 → 매번 find(1) 이 사슬을 탄다
    deep_a.append(1); deep_b.append(x)
```

실측 결과:

| S | 압축 없음 | 압축 있음 | 배율 |
| :--- | :--- | :--- | :--- |
| 2,000 | 0.027s | 0.0005s | 50× |
| 5,000 | 0.158s | 0.0027s | 59× |
| 10,000 | 0.639s | 0.0026s | 244× |
| 20,000 | 2.561s | 0.0061s | 420× |
| 100,000 | **34.2s** | **0.27s** | 127× |

## 6. 함정 & 배운 점

- **전역 `N ≤ S`는 틀린 판정이다.** `[1,1,1]/[2,2,2]`, `S=100,000` → `False`.
  용량은 전역이 아니라 **연결 요소 단위로** 부족해진다.
  → "총량은 충분한데 국소적으로 막히는" 구조를 먼저 의심한다.

- **2택 제약은 간선이다.** "각 원소가 두 후보 중 하나를 고르고, 후보는 한 번만 쓰인다"
  → 정점=후보, 간선=원소, 배정=방향 부여. 이 환원을 보면 `O(2^N)`이 `O(N·α)`가 된다.
  이분 매칭(`O(E√V)`)으로도 풀리지만 pseudoforest 판정이 훨씬 싸다.

- **`E ≤ V`가 충분조건인 이유를 알아야 한다.** 트리는 자식 방향, 사이클은 한 방향
  회전. "필요조건이니 아마 충분하겠지"로 넘기면 왜 되는지 설명할 수 없다.
  무작위 4000회 + 전수 1,678건으로 실제로 확인했다.

- **`find`는 반복문으로.** 재귀로 쓰면 `S = 100,000`에서 재귀 한도에 걸린다.

- **성능 케이스는 실제로 최악을 자극하는지 확인해야 한다.** 내 첫 성능 케이스(거대 사슬)는
  union 방향 때문에 트리가 평평해져서 경로 압축 부재를 전혀 잡지 못했다.
  변이 테스트가 이 **테스트 자체의 결함**을 드러냈고, 깊은 트리를 반복 조회하는
  적대적 입력으로 바꿔서야 34초 vs 0.27초로 갈렸다.
  → "느린 구현을 넣었을 때 실제로 실패하는가"를 확인하지 않은 성능 가드는 장식이다.

- **오라클도 검증 대상이다.** 브루트포스(정의 그대로)와 요소별 `E ≤ V`를 직접 세는
  독립 오라클을 서로 교차검증했다. 둘 다 본 풀이와 다른 논리라야 의미가 있다.
