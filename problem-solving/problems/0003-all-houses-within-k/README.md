# 0003. 모든 집과의 거리가 K 이하인 빈 땅 개수

- **출처**: 코딩테스트 유형 (격자 거리)
- **난이도**: Medium — 순진한 풀이는 시간초과, 관찰 하나로 O(NM)
- **유형**: 격자, 맨해튼거리, 좌표 회전 (L1 → L∞ 변환)
- **작성일**: 2026-08-14

---

## 1. 문제

> `N×M` 격자에서 **빈 땅(0)** 중 **모든 집(1)과의 거리가 K 이하**인 칸의 개수를 구한다.

**입력**

- `K`: 최대 허용거리, `1 ≤ K ≤ 800`
- `A`: `N×M` 행렬, `2 ≤ N, M ≤ 400`. 각 셀은 `0`(빈 땅) 또는 `1`(집)

**출력**

- 조건을 만족하는 빈 땅의 개수

**제약조건**

- 집이 **적어도 하나** 존재
- 거리는 **상하좌우 이동만** (대각선 불가)
- 통과 불가 칸(벽)에 대한 언급이 **없다** → 집도 지나갈 수 있다 (2번에서 근거를 다룬다)

**예제**

각 빈 땅의 **모든 집과의 최대거리**를 적으면 답이 눈에 보인다 (`H` = 집, `*` = 통과).

### 예시1 — `K = 2` → **2**

```
A = [[0,0,0,0],          5    4    4    5
     [0,0,1,0],    →     4    3    H    4
     [1,0,0,1]]          H    2*   2*   H
```

통과: `(2,1)`, `(2,2)`

### 예시2 — `K = 1` → **2**

```
A = [[0,1],              1*   H
     [0,0]]        →     2    1*
```

집이 하나뿐인데도 대각 방향 칸 `(1,0)`은 거리 2로 탈락한다.
대각선 이동이 불가하기 때문 — 상하좌우로 2칸 가야 한다.
통과: `(0,0)`, `(1,1)`

### 예시3 — `K = 4` → **8**

```
A = [[0,0,0,1],          4*   4*   5    H
     [0,1,0,0],          4*   H    4*   5
     [0,0,1,0],    →     5    4*   H    4*
     [1,0,0,0],          H    5    4*   4*
     [0,0,0,0]]          7    6    5    5
```

`5×4` 비정방 격자, 집 4개가 대각으로 흩어진 배치.
마지막 행은 거리 `7,6,5,5`로 전부 탈락 — 집들이 위쪽에 쏠려 있어서.
통과: `(0,0) (0,1) (1,0) (1,2) (2,1) (2,3) (3,2) (3,3)` — **8개**

## 2. 접근

### 먼저: "거리"가 정말 맨해튼거리인가

지문은 "상하좌우로만 이동"이라고 BFS를 암시한다. 하지만 **통과 불가 칸이 없으면**
최단 이동거리는 그냥 맨해튼거리 `|Δi| + |Δj|` 다. 우회할 이유가 없기 때문.

이 가정은 검증에서 실제로 확인했다 — 집마다 BFS를 돌려 상하좌우 이동을 시뮬레이션한
오라클과 무작위 200케이스에서 전부 일치한다.

> **주의**: 만약 집을 *통과 불가*로 취급하는 변형이라면 이 풀이는 틀린다.
> 실측 반례: `[[0,1,0],[0,1,0],[1,1,1]]`, `K=3` → 집 통과 가능이면 `2`, 통과 불가면 `0`.
> 이 문제는 벽 언급이 없으므로 통과 가능이 맞다.

### 버린 방법: 집마다 BFS — O(H·N·M)

집 하나마다 BFS를 돌려 각 빈 땅의 최대거리를 갱신하는 방식.

- 최악의 경우 집이 `400×400 / 2 = 80,000`개
- 연산량 `80,000 × 160,000 = 1.28 × 10^10` — **실측으로 계산해봐도 불가**

집 개수 `H`가 답에 곱해지는 구조 자체가 문제다. `H`를 없애야 한다.

### 관찰: 최대거리는 집 4개만으로 결정된다

`max` over 집들의 `|i-hi| + |j-hj|` 를 절댓값 전개하면 부호 조합이 4가지다:

```
|Δi| + |Δj| = max( +Δi+Δj, +Δi-Δj, -Δi+Δj, -Δi-Δj )
```

`Δi = i-hi`, `Δj = j-hj` 를 넣고 정리하면 `(i+j)`와 `(i-j)`만 남는다.

### 최종: 좌표 회전 (L1 → L∞)

```
u = i + j
v = i - j
```

이렇게 45° 회전하면 **맨해튼거리가 체비쇼프거리로 바뀐다**:

```
|i₁-i₂| + |j₁-j₂|  =  max( |u₁-u₂|, |v₁-v₂| )
```

그러면 모든 집에 대한 최대거리는

```
max over 집 h  of  max(|u-u_h|, |v-v_h|)
  = max( max_h |u-u_h| , max_h |v-v_h| )          ← max 끼리는 분리 가능
  = max( u-min_u, max_u-u, v-min_v, max_v-v )
```

**집이 8만 개든 1개든 필요한 정보는 `min_u, max_u, min_v, max_v` 4개뿐이다.**
빈 땅 하나당 판정이 O(1)이 된다.

---

## 3. 알고리즘

```
# 1패스 — 집들의 u, v 범위만 수집 (집 좌표 저장 불필요)
min_u = min_v = +∞ ; max_u = max_v = -∞
for (i, j) where A[i][j] == 1:
    u, v = i+j, i-j
    min_u = min(min_u, u) ; max_u = max(max_u, u)
    min_v = min(min_v, v) ; max_v = max(max_v, v)

# 2패스 — 빈 땅마다 O(1) 판정
count = 0
for (i, j) where A[i][j] == 0:
    u, v = i+j, i-j
    worst = max(u - min_u, max_u - u, v - min_v, max_v - v)
    if worst <= K: count += 1

return count
```

두 패스 모두 격자를 한 번씩 훑는다. 끝.

## 4. 복잡도

| | 이 풀이 | 집마다 BFS |
| :--- | :--- | :--- |
| 시간 | **O(N·M)** | O(H·N·M) |
| 공간 | **O(1)** 추가 | O(N·M) |
| 400×400 최악 | **0.03초** (실측) | 1.28×10^10 연산 |

**근거**: `N·M = 160,000`. 패스 2회로 32만 번 연산.
집 개수와 무관하다 — 집이 8만 개인 밀집 격자에서도 실측 0.04초 (검증 케이스 9번).

정수 오버플로 걱정 없음: `u`의 범위는 `0 ~ 798`, `v`는 `-399 ~ 399`.

### 예시3만으로는 못 잡는 버그가 있다

예시3의 **마지막 행은 거리 `7,6,5,5`로 전부 탈락**한다. 그래서 "마지막 행을 아예 안 보는"
off-by-one 버그를 넣어도 예시3은 여전히 `8`을 내놓는다 (실측 확인).
예시1·2가 잡아주긴 하지만, 비정방 격자에서 행 경계를 확인하려면
**마지막 행에 통과 칸이 있는 케이스**가 따로 필요하다:

```
edge = [[0,0,0,0],        5    4*   3*   4*
        [0,1,0,0],        4*   H    2*   3*
        [0,0,0,0],   →    3*   2*   2*   3*     K=4 → 16
        [0,0,1,0],        3*   2*   H    4*
        [0,0,0,0]]        4*   3*   4*   5
```

마지막 행 `(4,0) (4,1) (4,2)` 가 통과하므로 행 누락 버그가 즉시 드러난다.

실행:

```bash
python3 problem-solving/problems/0003-all-houses-within-k/solution.py
# → OK  (0.33초)
```

### 변이 테스트 — 검증이 실제로 지키는지 확인

구현을 일부러 깨뜨려 검증 케이스가 잡아내는지 실측:

| 변이 | 결과 |
| :--- | :--- |
| `v`축 무시 (`u`만으로 판정) | `[2x2 집 1개 K=1] expected=2 actual=3` — 잡힘 |
| `max_v - v` 항 누락 | `[예시1] expected=2 actual=4` — 잡힘 |
| 경계 부등호 `<= K` → `< K` | `[예시1] expected=2 actual=0` — 잡힘 |
| 집 칸도 카운트 (`!= 0` 조건 제거) | `[2x2 집 1개 K=1] expected=2 actual=3` — 잡힘 |
| 체비쇼프를 합으로 오해 | `[예시1] expected=2 actual=0` — 잡힘 |
| `min`/`max` 갱신 부등호 뒤바꿈 | `[2x2 집 1개 K=1] expected=2 actual=3` — 잡힘 |
| 마지막 **행** 누락 (`range(n-1)`) | `[예시1] expected=2 actual=0` — 잡힘 |
| 마지막 **열** 누락 (`range(m-1)`) | `[예시2] expected=2 actual=1` — 잡힘 |

8개 전부 잡힌다. **통과하는 테스트가 아니라 깨지면 실패하는 테스트**임을 확인.

무효 변이도 하나 확인했다: `range(m)` → `range(len(row))` 는 `row = A[i]` 이므로
`len(row) == m`. 의미가 같아서 안 잡히는 게 정상이다 — 검증 빈틈이 아니다.

## 6. 함정 & 배운 점

- **"상하좌우 이동"을 보면 반사적으로 BFS를 짜는데, 벽이 없으면 BFS가 필요 없다.**
  최단거리 = 맨해튼거리. 이걸 놓치면 O(H·N·M)으로 시간초과.
  → 격자 문제에서 **통과 불가 칸이 있는지**를 제약조건에서 먼저 확인한다.
- **`max`(모든 집) 형태는 집 전체를 볼 필요가 없다.** 절댓값 합을 부호 조합으로 전개하면
  극단값 몇 개로 환원된다. 반대로 **`min`(가장 가까운 집)이라면 멀티소스 BFS 한 번**으로 끝난다.
  `max`와 `min`은 완전히 다른 문제다 — 멀티소스 BFS는 `min`만 준다.
- **회전 좌표 `u=i+j, v=i-j` 는 맨해튼거리 문제의 표준 도구.** L1 → L∞ 변환.
  "가장 먼 점", "지름", "체비쇼프 중심" 류 문제에서 계속 나온다.
- **경계 부등호가 가장 흔한 오답 지점.** `K` "이하"이므로 `<=`. 변이 테스트에서
  `<`로 바꾸자 지문 예제가 `2 → 0`으로 무너졌다.
- **예시2가 대각선 금지를 정확히 찌른다.** `[[0,1],[0,0]]` `K=1` 에서 집의 대각 방향 칸
  `(1,0)`은 거리 2로 탈락한다. 대각선을 허용하는(체비쇼프) 구현이면 1로 계산해 통과시켜버린다.
  집이 하나뿐인 최소 격자가 거리 정의 자체를 검증하는 케이스가 된다.
- **예제가 통과한다고 검증이 충분한 건 아니다.** 예시3의 마지막 행은 전부 K 초과라서
  "마지막 행을 안 보는" 버그를 넣어도 답이 `8`로 유지된다(실측). 예제는 **정답 확인용**이고,
  경계 커버리지는 따로 설계해야 한다 — 마지막 행에 통과 칸이 있는 케이스를 추가한 이유.
- **가정을 검증에 박아넣는다.** "맨해튼거리로 치환 가능"은 *가정*이다. BFS 오라클을
  검증 케이스로 넣어 그 가정 자체를 200케이스로 확인했다. 가정을 주석으로만 남기면
  나중에 벽 있는 변형을 만났을 때 조용히 틀린다.
- **오라클도 검증 대상이다.** 브루트포스와 BFS 오라클을 서로 교차검증했다.
  오라클이 틀리면 통과 신호가 거짓이 된다.
