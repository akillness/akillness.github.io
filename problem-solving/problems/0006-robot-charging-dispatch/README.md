# 0006. 로봇 충전 스테이션 배차 — 최대 이동거리 최소화

- **출처**: 코딩테스트 대비 (현대오토에버 RX기술팀 · 이기종로봇관제 도메인)
- **난이도**: Hard — BFS + 이분탐색 + 이분매칭 3단 조합
- **유형**: 그래프, 다중소스 BFS, 이분탐색, 이분매칭(Kuhn)
- **작성일**: 2026-08-20

> **0003과 짝으로 보세요.** 0003은 벽이 없어 맨해튼거리로 환원됐습니다.
> 이 문제는 **벽이 있어서 그 트릭이 깨집니다.** 경계를 몸으로 익히는 게 목적입니다.

---

## 1. 문제

> 창고 격자에 로봇 `R`대와 충전 스테이션 `S`개가 있다.
> 각 로봇을 **서로 다른** 스테이션에 1:1 배정할 때,
> **가장 오래 걸리는 로봇의 이동거리**를 최소화하라.

**입력**

- `grid`: `N×M`, `0`=이동 가능, `1`=장애물
- `robots`: 로봇 좌표 리스트
- `stations`: 스테이션 좌표 리스트

**출력**

- 최적 배정에서의 최대 이동거리. 배정 불가면 `-1`

**제약**

- 이동은 상하좌우만
- 한 스테이션에 로봇 하나 (1:1)
- `R ≤ S` 여야 배정 가능

**예제**

```
grid = [[0,0,0,0],       로봇 (0,0), (2,0)
        [0,1,1,0],       스테이션 (0,3), (2,3)
        [0,0,0,0]]       → 3
```

---

## 2. 접근

### 왜 0003의 회전 트릭이 안 되는가

0003에서는 장애물이 없어 `거리 = |Δi|+|Δj|`였고, `u=i+j, v=i-j` 회전으로 O(1) 판정이 됐습니다.
**벽이 하나라도 있으면 이게 무너집니다.**

```
[[0,1,0],        로봇 (0,0) → 스테이션 (0,2)
 [0,1,0],        맨해튼: 2
 [0,0,0]]        실제(BFS): 6   ← 아래로 우회
```

검증 케이스에 이 대조를 넣어 두었습니다 (`_manhattan_answer`).
무작위 400케이스에서 맨해튼과 실제 답이 갈리는지도 확인합니다 — 안 갈리면 테스트가 너무 쉽다는 뜻이라 실패시킵니다.

### 버린 방법 1: 로봇마다 BFS

로봇 `R`대 각각 BFS → `O(R·N·M)`.
스테이션이 로봇보다 적은 경우가 흔하므로 **스테이션 기준이 더 싸다**. `O(S·N·M)`.

### 버린 방법 2: 그리디

"각 로봇이 가장 가까운 빈 스테이션을 집는다"는 틀립니다.

```
복도 [0,0,0,0,0]
로봇 A(0), B(1) / 스테이션 (1), (4)

그리디: A가 가까운 (1)을 먼저 집음 → B는 (4)로 3칸... 이 경우는 맞지만
순서를 바꾸면: B가 (1)을 집음 → A는 (4)로 4칸 → 최대 4 (오답)
최적: A→(1)=1, B→(4)=3 → 최대 3
```

먼저 집는 순서에 따라 답이 달라지므로 그리디는 안전하지 않습니다.

### 최종: 이분탐색 + 이분매칭

"최대값을 최소화"는 **답을 고정하고 가능성만 판정**하는 형태로 바꿉니다.

```
"최대 이동거리 L 이하로 전원 배정 가능한가?"
→ 거리 ≤ L 인 (로봇, 스테이션) 간선만 남기고 이분매칭
→ 완전매칭 되면 가능
```

`L`이 커지면 간선이 늘어나므로 **판정이 단조**입니다. 이분탐색이 성립합니다.

---

## 3. 알고리즘

```
1. 스테이션마다 BFS → cost[robot][station] (도달 불가 = -1)
2. 후보 거리값 집합을 정렬 (연속 정수 전체를 훑을 필요 없음)
3. 후보에 대해 이분탐색:
     mid 거리 이하 간선만으로 Kuhn 이분매칭
     전원 매칭되면 → 더 작은 값 시도
     안 되면      → 더 큰 값 시도
4. 매칭에 성공한 최소 거리 반환
```

후보를 거리값 집합으로 잡는 게 포인트입니다. `0..N*M` 전체를 이분탐색하면 불필요한 반복이 생깁니다.

---

## 4. 복잡도

| 단계 | 복잡도 |
| :--- | :--- |
| BFS (스테이션별) | `O(S · N · M)` |
| 이분탐색 | `O(log(S·R))` 회 |
| 매칭 1회 (Kuhn) | `O(R · R · S)` |
| **전체** | `O(S·N·M + log(S·R) · R²·S)` |

실측: `100×100` 격자, 스테이션 20개, 로봇 20대 → 5초 상한 내 완주 (검증 케이스 8번)

## 5. 검증

| 케이스 | 목적 |
| :--- | :--- |
| 기본 예제 (단일/2대) | 벽 우회 경로 |
| **U자 벽** | `BFS=6` vs `맨해튼=2` — **회전 트릭 무효 확인** |
| 완전 차단 | 도달 불가 → `-1` |
| 로봇 0대 / 이미 스테이션 위 | 경계값 |
| 스테이션 부족 / 여유 | `R > S` → `-1` |
| **병목 배정** | 그리디가 틀리는 케이스 (최대값 최소화) |
| **무작위 교차 1200회** | 순열 완전탐색 오라클과 일치 (유효 케이스 500개 미달 시 실패) |
| **맨해튼 대조 400회** | 벽이 있으면 실제로 답이 갈리는지 (안 갈리면 실패) |
| `100×100` 성능 | 5초 상한 가드 |

실행:

```bash
python3 problem-solving/problems/0006-robot-charging-dispatch/solution.py
# → OK  (0.21초)
```

### 변이 테스트

| 변이 | 결과 |
| :--- | :--- |
| BFS 대신 맨해튼거리 | `[U자 벽 우회 → 6] expected=6 actual=2` — 잡힘 |
| 이분매칭 대신 그리디 | `[무작위 교차] expected=2 actual=3` — 잡힘 |
| 도달 불가(`-1`)를 통과시킴 | `[무작위 교차] expected=-1 actual=1` — 잡힘 |
| 이분탐색을 최대값으로 고정 | `[2대 배정] expected=3 actual=5` — 잡힘 |
| BFS에서 벽 검사 제거 | `[U자 벽 우회 → 6] expected=6 actual=2` — 잡힘 |
| `R > S` 가드 제거 | **안 잡힘 — 무효 변이** (아래) |

**무효 변이 확인**: `R > S` 가드는 **빠른 경로일 뿐 정확성 가드가 아닙니다.**
가드를 빼도 이분매칭이 이미 완전매칭 실패로 `-1`을 반환합니다.
무작위 4000케이스(로봇>스테이션 상황 다수 포함)에서 원본과 **불일치 0건**으로 확인했습니다.
검증 빈틈이 아니라 의미가 같은 변이입니다.

## 6. 함정 & 배운 점

- **"벽이 있는가"가 알고리즘 전체를 가릅니다.** 0003은 벽이 없어 O(NM) 회전 트릭으로 끝났고,
  이 문제는 벽 때문에 BFS가 필수입니다. → 격자 문제에서 **제약조건의 장애물 유무를 가장 먼저 확인**한다.
- **"최대값을 최소화"는 이분탐색 + 판정 문제로 바꾼다.** 직접 최적해를 찾으려 하면 조합이 폭발합니다.
  판정이 단조인지만 확인하면 됩니다.
- **1:1 배정 + 최대값 최소화 = 이분매칭.** 그리디는 집는 순서에 답이 좌우돼 틀립니다.
  병목 케이스를 검증에 명시적으로 넣어 이걸 잡습니다.
- **다중소스 BFS 방향을 고르면 비용이 달라집니다.** 로봇 기준 `O(R·NM)` vs 스테이션 기준 `O(S·NM)`.
  더 적은 쪽에서 출발합니다.
- **이분탐색 후보를 거리값 집합으로 좁힌다.** `0..N·M` 전체를 훑으면 존재하지 않는 거리에서도 매칭을 돌립니다.
- **오라클이 커버하는 범위를 검증에 못 박는다.** 무작위 케이스가 다 무효로 걸러질 수 있어
  "유효 케이스 500개 미달 시 실패", "맨해튼과 한 번도 안 갈리면 실패" 단정을 넣었습니다.
  통과하는 테스트가 아니라 **의미 있는 입력을 실제로 봤는지**를 검증합니다.
- **안 잡힌 변이는 먼저 무효 여부를 따진다.** `R > S` 가드 제거가 안 잡혔지만,
  4000케이스 대조로 의미가 같음을 확인했습니다. 성급히 테스트를 추가하면 중복만 늘어납니다.
