# LLM Lingo: Must-Know Terms, Regrouped with Source-Pinned Definitions

The original note was a two-part glossary table credited to an external LinkedIn author, plus a pasted multi-token-prediction summary and an unrelated link. A copied table is exactly what a "low value content" flag targets: terms without decisions. This rewrite keeps the same terms but regroups them by the decision each term informs — architecture, prompting, retrieval, tuning, compression — with definitions pinned to primary sources retrieved 2026-10-14. (Original table credit: [Aishwarya Naresh Reganti](https://www.linkedin.com/in/areganti/recent-activity/all/).)

## Architecture terms: what the model is

| Term | Source-pinned definition |
|:-----|:-------------------------|
| `Foundation Model` | A large model pretrained on broad data and adaptable to many tasks (the term's canonical use: Bommasani et al., 2021). "LLM designed for human-like text" is only the language-model instance of it. |
| `Transformer` | The attention-based architecture of Vaswani et al. (arXiv:1706.03762, 2017): self-attention plus parallel processing, replacing recurrence. Every term below assumes this substrate. |
| `Context-Length` | The maximum input window (tokens, not words) the model conditions on when generating. It bounds RAG payloads, few-shot examples, and agent histories alike. |

## Prompting terms: what you feed the model

| Term | Source-pinned definition |
|:-----|:-------------------------|
| `Prompting` | Crafting inputs to steer generation. The technique became a discipline with GPT-3 (Brown et al., arXiv:2005.14165, 2020), which showed few-shot and zero-shot task performance without weight updates. |
| `Few-Shot Learning` | Including a handful of input-output examples in the prompt. Works because the pretrained model already contains the task pattern; fails when the pattern is absent or the window is too small. |
| `Zero-Shot Learning` | Instructions only, no examples. Relies entirely on pretraining coverage — the reason the KILT-NQ judge rankings above shift with the judge model. |
| `In-Context Learning` | The umbrella mechanism: task adaptation inside the forward pass, no gradient steps. Distinct from fine-tuning below. |

## Retrieval terms: what grounds the model

| Term | Source-pinned definition |
|:-----|:-------------------------|
| `RAG` | Retrieval-Augmented Generation (Lewis et al., arXiv:2005.11401, 2020): append retrieved passages to the prompt so the response is grounded in documents, not just weights. See also the RAG paper-list post on this blog. |
| `Knowledge Base (KB)` | The document collection retrieval draws from. RAG quality is bounded by KB coverage and freshness before any model choice matters. |
| `Vector Database` | Stores KB embeddings for similarity search. It is an index, not a truth source: stale vectors silently degrade answers. |
| `Hallucination` | Fluent non-factual output. RAG, calibration, and abstention reduce it; no prompting trick removes it. |

## Tuning terms: what changes the weights

| Term | Source-pinned definition |
|:-----|:-------------------------|
| `Fine-Tuning` | Further training on task data. Full fine-tuning updates all weights; everything below is a cheaper point on the same trade-off curve. |
| `Instruction Tuning` | Fine-tuning on instruction-response pairs so the model follows directives and formats. |
| `SFT` | Supervised Fine-Tuning: the labeled-data phase that precedes preference optimization in most RLHF pipelines. |
| `Transfer Learning` | Reusing pretrained representations for data-scarce tasks — the reason fine-tuning beats training from scratch. |
| `Contrastive Learning` | Teaching similarity structure (pull matches together, push mismatches apart); the same objective behind embedding models used in RAG retrieval. |
| `Reinforcement Learning` | Trial-and-error optimization against rewards/penalties on generated outputs. |
| `Reward Modeling` | Learning the reward function itself from ranked outputs — the step that makes RLHF possible. |
| `RLHF` | Reinforcement Learning from Human Feedback: human rankings train the reward model, which then steers the LLM. |

## Compression terms: what shrinks the model

| Term | Source-pinned definition |
|:-----|:-------------------------|
| `PEFT` | Parameter-Efficient Fine-Tuning: update a small fraction of weights. The family; LoRA and freeze tuning are members. |
| `LoRA` | Low-Rank Adaptation (Hu et al., arXiv:2106.09685, 2021): inject small trainable rank-decomposition matrices and freeze the rest. The default PEFT choice for LLM adaptation. |
| `Freeze Tuning` | Keep most weights frozen and train task layers only. Simpler than LoRA, weaker when the task needs distributed changes. |
| `Quantization` | Lower weight precision (INT8/4-bit) to cut memory and speed inference. Detailed comparison in this blog's LLM Quantization post (/posts/llm-types/): GPTQ, AWQ, QAT/PTQ, GGUF presets. |
| `Pruning` | Remove surplus connections or parameters. Effective with retraining or calibration; naive pruning collapses capability. |

## What is Multi-Token Prediction Training?

The original note pasted a summary of Gloeckle et al. (arXiv:2404.19737, 2024) without naming the paper. Pinned facts: standard training predicts only the next token; multi-token prediction adds independent output heads on a shared trunk to predict the next n tokens, with a memory-efficient forward/backward implementation. Reported effects: higher sample efficiency, stronger induction heads and algorithmic reasoning, pronounced gains on generative coding tasks (13B models solving 12% more HumanEval and 17% more MBPP problems than next-token baselines), and up to 3x faster inference via self-speculative decoding with 4-token prediction. The honest caveat: gains concentrate on generative benchmarks; the paper does not claim uniform wins.

## Limitations

- The KILT-NQ judge-ranking image is presented as the original's evaluation illustration; judge rankings shift with judge choice and should not be read as a model leaderboard.
