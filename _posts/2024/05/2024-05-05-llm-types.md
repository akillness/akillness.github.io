# LLM Quantization: GPTQ, AWQ, QAT, PTQ, GGML, GGUF, and K-quants

The original version of this note was a seven-line acronym list. That shape is exactly what a "low value content" flag targets: links without a decision. This rewrite keeps the same seven methods but adds the missing decision — what each method quantizes, what it preserves, and when it is the wrong choice — pinned to primary sources retrieved 2026-10-14.

## Why the choice matters

All seven names reduce the same cost (memory and inference latency) but they intervene at different points. Weight-only post-training methods (GPTQ, AWQ) keep the training pipeline untouched and compress a finished model. Training-aware methods (QAT) move the cost earlier into training. Format methods (GGML, GGUF, K-quants) decide how the compressed weights are stored, memory-mapped, and served. Confusing a quantization algorithm with a file format is the most common mistake in this list.

## What each method actually does

**GPTQ** is one-shot weight quantization based on approximate second-order information (Frantar et al., arXiv:2210.17323v2, revised 2023-03-22, ICLR 2023). The verified claims are specific: a 175B-parameter GPT model quantizes in about four GPU hours down to 3-4 bits per weight with negligible accuracy degradation versus the uncompressed baseline, enabling a 175B model inside a single GPU for generative inference. The paper reports end-to-end inference speedups over FP16 of around 3.25x on NVIDIA A100 and 4.5x on NVIDIA A6000. It also explores the extreme regime (2-bit and ternary) with reasonable accuracy. Implementation: <https://github.com/IST-DASLab/gptq>. What the README alone omits: the accuracy claim depends on calibration data and the second-order approximation, so out-of-distribution prompts can deviate from the paper's benchmarks.

**AWQ** is activation-aware weight quantization (Lin et al., arXiv:2306.00978v6, revised 2026-04-25; MLSys 2024 Best Paper). The core finding is that only about 1% of weights are salient, and salience should be identified from the activation distribution, not weight magnitude. AWQ scales up salient channels through an equivalent transformation so they survive low-bit rounding, without backpropagation or reconstruction, which is why it generalizes across domains and to instruction-tuned and multimodal models. Alongside it, TinyChat (4-bit inference framework with kernel fusion and platform-aware packing) reports more than 3x speedup over Hugging Face FP16 on desktop and mobile GPUs, including a 70B Llama-2 deployment on mobile GPUs. Implementation: <https://github.com/mit-han-lab/llm-awq>. What the announcement omits: the 1% figure is empirical, and the offline activation statistics must match the deployment distribution.

**QAT (Quantization-Aware Training)** inserts simulated quantization into training so the network adapts its weights to rounding error. The linked reference (arXiv:2305.17888) is one instance, not the definition. Use QAT when retraining is affordable and the last accuracy point matters; avoid it when only a finished checkpoint is available.

**PTQ (Post-Training Quantization)** quantizes a finished model without retraining. It is cheaper than QAT and the right default for serving an existing checkpoint, but at very low bit widths it degrades faster than QAT or salient-weight protection unless calibrated carefully.

**GGML** is the original C++ tensor library and runtime optimized for CPU inference of models including LLaMA and Falcon series (<https://github.com/ggerganov/ggml>). Treat it as the executor, not the compression algorithm.

**GGUF** is the successor file format to GGML, GGMF, and GGJT, specified in `ggml/docs/gguf.md`. It stores the full model in one file with a key-value metadata header (for example `general.architecture`, `general.quantization_version`, `general.alignment`), supports `mmap` loading, and adds a naming convention of `[Sidecar]BaseName-SizeLabel-FineTune-Version-Encoding-Type-Shard.gguf` (for example `Mixtral-8x7B-v0.1-KQ2.gguf`). Conversion paths such as safetensors-to-GGUF and CPU/GPU/MPU portability are format properties, not accuracy claims.

**K-quants** (for example `q2_K`, `q3_K_S`, `q3_K_L`, `Q4_K_M`) are GGUF quantization presets that vary bit width per tensor by importance. They are a packaging choice inside the GGUF ecosystem: smaller presets cut memory further but increase perplexity risk on sensitive layers.

## Comparison: pick by constraint, not by name

| Method | Intervenes at | Needs retraining | Preserves | Fails when |
|---|---|---|---|---|
| GPTQ | weights, post-training | No | accuracy at 3-4 bits, single-GPU serving | calibration mismatched; 2-bit pushed too far |
| AWQ | salient weights, post-training | No | 1% salient channels via activation stats | activation stats not representative |
| QAT | training loop | Yes | last-point accuracy at low bits | no training budget or data |
| PTQ | finished checkpoint | No | serving cost quickly | very low bits without calibration |
| GGML | runtime | N/A | CPU execution | mistaken for an accuracy method |
| GGUF | file format | N/A | single-file deploy, mmap, metadata | mistaken for an accuracy method |
| K-quants | GGUF preset | No | memory/quality knob per tensor | smallest preset on sensitive layers |

## Trade-offs verified from the sources

- Speed numbers (GPTQ 3.25x/4.5x, TinyChat 3x+) are hardware- and kernel-specific. They do not transfer automatically to a different GPU, batch size, or serving stack.
- Bit width is not a quality score. A 4-bit AWQ/GPTQ checkpoint with matched calibration routinely beats a naive 8-bit rounding with mismatched calibration.
- Format and algorithm compose: a common production path is GPTQ- or AWQ-quantized weights stored as GGUF K-quants for local serving. Evaluate the pair, not either alone.

## Limitations

- This rewrite did not re-run quantization benchmarks; paper numbers are reported as verified source claims, and serving numbers are inferred to the reader's hardware until measured locally.
- The linked QAT reference is a single paper, not a survey of QAT practice.
- GGUF spec details (tensor types, KV registry) evolve; the naming-convention regex and `general.*` keys reflect the spec as retrieved 2026-10-14.
